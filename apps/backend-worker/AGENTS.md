# apps/backend-worker

- Cloudflare Workers entrypoint for `apps/backend`. `src/worker.ts` exports `build(env, overrides?)`, which wires concrete dependencies (DAO → repository → service) into `createApp` and `createJobs` from `apps/backend`, and the Worker itself: `fetch` serves the Hono app, `scheduled` runs the cron jobs (`triggers.crons` in `wrangler.jsonc`: every minute = notifications, `0 18 * * *` = purge). Routes and business logic stay in `apps/backend`.
- Workers-only code lives here, never in `apps/backend`: DAOs backed by Cloudflare bindings (`src/dao/*.d1.ts`, `src/dao/image-store.r2.ts`) implementing the interfaces in `backend/src/dao/*.interface.ts`, and anything that touches `env` bindings.
- One Worker serves the whole app: `apps/backend` at `/api`, and the `apps/frontend` build (`../frontend/dist`) at `/` as static assets (`assets` in `wrangler.jsonc`: SPA fallback to `index.html`, `run_worker_first` for `/api/*`; response headers come from `apps/frontend/public/_headers`). `frontend` is a devDependency only to order builds: run `vp run -t backend-worker#build` (or `vp run -r build`) so the frontend builds once before the dry-run bundle; `deploy` builds the frontend itself. `dev` only creates an empty `../frontend/dist` if missing, since in development the frontend is served by `vp run frontend#dev` (which proxies `/api` here).
- Config is `wrangler.jsonc`: `DB` (D1), `IMAGES` (R2), crons, and no `vars` (root `AGENTS.md` "Public config values for the frontend"). After adding bindings, run `vp run backend-worker#cf-typegen` to regenerate `worker-configuration.d.ts` (untracked). `database_id` is a placeholder until `wrangler d1 create chocosuke`.
- Schema: `migrations/*.sql` (never edit an applied one; add the next number). Apply locally with `wrangler d1 migrations apply DB --local`; `deploy` applies them to the remote database before deploying the code.
- Secrets: `SESSION_SECRET` (required), and `GOOGLE_CLIENT_ID`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (optional; Google login / Web Push fail while unset). Typed in `WorkerEnv` (`src/worker.ts`). `DEV_LOGIN=true` (`.dev.vars` only, never a real secret) turns on a development login while `GOOGLE_CLIENT_ID` is unset: the credential `dev:<name>` signs in as that account, so the app runs locally without a Google client. Use `wrangler secret put`, locally `.dev.vars` (gitignored, never committed).
- Tests run real SQL: `src/dao/test-env.ts` starts a local, in-memory D1/R2 with `wrangler`'s `getPlatformProxy` and applies the migrations. DAO tests sit next to their DAO (`*.d1.test.ts`); `src/worker.test.ts` drives the whole API through `build()` with Google, Web Push and the clock faked.
