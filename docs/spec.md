# チョコスケ（chocosuke）

Calendar-based schedule management app.  
チョコスケ - 家族で共有するカレンダーアプリ。

## 総論

### 目的

ユーザーは"Googleでログイン"したあと、自分の予定をカレンダーに登録・参照できるアプリ。  
家族等とグループを1つ作成でき、個人・グループに複数の予定を作成できる。  
例えば個人-仕事、個人-勉強会の予定を作成、グループ-一郎、グループ-花子の予定を作成した場合、グループメンバーに公開されるのはグループ-一郎、グループ-花子の予定のみとなる。  
各予定はチップで表示され、簡単にフィルターできる（例：個人-仕事のみ表示する）。

### 利用イメージ

- 設定
  - 初回登録
  - グループ作成→QRコードで招待
- 予定登録
- 予定確認
- 予定通知（PWAプッシュ通知）

### 提供形態

- Webアプリ / PWAとして提供する。主な利用環境はiOS/Android/Win/Macとする。
- スマートフォン向けとし、iPad等のタブレットでも見やすくする。スマートフォンは縦表示のみ、タブレットは縦・横の両方に対応する（「共通ルール > 画面」参照）。
- 日本国内向けのサービスとする。日付の判定と日時の表示はAsia/Tokyoとする（コード上は `packages/utils/src/date/zone.ts` の `TIME_ZONE_OFFSET_MINUTES`）。

### データの単位

- データは「個人」単位または「グループ」単位で管理する。
- 個人のデータは本人だけが参照・操作できる。グループのデータはグループの全メンバーが参照・操作できる（「権限」参照）。
- グループに参加していないユーザーは、個人のデータだけを利用する。

### 用語

<!-- 本文で使う用語を定義する。定義した用語は本文で言い換えない。 -->

| 用語           | 意味                                                                                   |
| -------------- | -------------------------------------------------------------------------------------- |
| 予定           | イベントのまとまり（例: 「仕事」の予定には10/5のイベント、10/6のイベント等が含まれる） |
| 公開範囲       | 予定の公開先。個人 / グループ                                                          |
| 個人の予定     | 公開範囲が個人の予定。ユーザー本人だけに表示される                                     |
| グループの予定 | 公開範囲がグループの予定。グループの全メンバーに公開される                             |
| イベント       | 例: 10/5 10:00-11:00の打合せ                                                           |
| トピック       | イベントの分類。予定ごとにトピックマスタを持つ（例: 「仕事」の予定に「会議」「出張」） |
| 画像           | イベントに添付する画像（例: メールのスクリーンショット）                               |
| グループ       | 家族等でデータを共有する単位。1ユーザーが参加できるグループは0〜1つ                    |
| 作成者         | グループを作成したユーザー                                                             |
| メンバー       | グループに参加しているユーザー（作成者を含む）                                         |
| メンバー名     | グループ内で表示するユーザーの名前。グループ作成・参加時に指定する                     |
| 招待リンク     | グループに参加するためのURL。QRコードとしても表示する                                  |
| ローカルDB     | 端末のブラウザのIndexedDB。取得したデータと画面の表示状態を永続化する                  |

### 権限

<!-- ロールごとに操作の可否を ○ / × / －（該当しない）で示す。 -->

個人のデータ（個人の予定・そのトピック・イベント・画像）は本人だけが参照・登録・変更・削除できる。グループのデータは次のとおり。

| 操作                                                       | 作成者 | メンバー（作成者以外） | グループ外のユーザー |
| ---------------------------------------------------------- | ------ | ---------------------- | -------------------- |
| グループの予定・トピック・イベント・画像の参照             | ○      | ○                      | ×                    |
| グループの予定・トピック・イベント・画像の登録・変更・削除 | ○      | ○                      | ×                    |
| グループ名の変更                                           | ○      | ×                      | ×                    |
| 招待リンク（QRコード）の表示・再発行                       | ○      | ○                      | ×                    |
| 自分のメンバー名の変更                                     | ○      | ○                      | －                   |
| 他のメンバーの除外                                         | ○      | ×                      | ×                    |
| グループからの脱退                                         | ○（※） | ○                      | －                   |
| グループの削除                                             | ○      | ×                      | ×                    |
| グループの作成・招待リンクからの参加                       | －     | －                     | ○                    |

- ※ 作成者が脱退すると、残るメンバーのうち参加日時が最も古いメンバーが作成者になる。残るメンバーがいない場合はグループを削除する。
- 権限は画面とAPIの両方で検証する。

### 共通ルール

<!-- 複数の機能にまたがるルール。各論では繰り返さず、ここを参照する。 -->

- 入力
  - 文字数・件数の上限は「リミット値」参照。上限は画面とAPIの両方でチェックする。
  - 文字数は見た目の1文字を1文字と数える（全角・半角・絵文字とも1文字）。
  - 名前・タイトル等の文字列は前後の空白を除去して保存する。除去後に空になる場合は未入力とみなす。
- 画面
  - 画面下部にボトムナビゲーション（カレンダー / 予定 / グループ / 設定）を表示する（ログイン・同意・グループ参加画面を除く）。
  - ホーム画面から全画面表示（PWA）している場合、ボトムナビゲーションは画面下端（iPhoneのホームインジケーター）に接するため、高さを 76px にする（ブラウザのタブでは Vuetify 既定の 56px）。
  - スマートフォン（幅600px未満）は縦表示のみ対応する。横向きにした場合は「縦向きでご利用ください」と表示する。
  - タブレット（幅600px以上）は縦・横の両方に対応する。横表示では月表示の右側に選択日のイベント一覧を表示する。
  - テーマはライトのみとする。
  - アプリアイコン（PWA・ファビコン・ログイン画面のロゴ）は、画面デザインと同じ Material Symbols Rounded の `calendar_month`（白）を角丸の正方形（`#2B5C8A`）に置いたもの。
  - 二択などの切り替え（月/週、個人/グループ、バー/ドット、日曜日/月曜日）はボタングループ（`v-btn-toggle`）で表示する。全体を1つの枠線で囲み（角丸8px）、選択中のボタンを `primary-container` で塗る。見た目は共通の既定値（`plugins/vuetify.ts`）で揃える。
  - API エラー時は画面下部にスナックバーでメッセージを表示する。エラー（続行できない）は少し透過した赤の背景に白文字、それ以外のお知らせ（「招待リンクをコピーしました」等）は濃いグレーの背景に白文字で表示する。
  - アプリの更新: 新しいバージョンが公開されると、画面下部に「新しいバージョンがあります」のスナックバー（濃いグレー、「後で」「更新」ボタン付き）を閉じるまで表示する。「更新」で新しいバージョンに切り替えて再読み込みする。「後で」で閉じた場合は、次にアプリを開いたときに再び表示する。入力中の内容を失わないよう、自動では切り替えない。ほかのスナックバーの表示中は隠れる。
  - 新しいバージョンの確認は、アプリを開いたとき・アプリが前面に戻ったとき・1時間ごとに行う（ホーム画面のアプリはバックグラウンドから戻るだけで、ページを読み込み直さないことが多いため）。
- 日付・日時の表示
  - 年を含める場合は `例: 2026/09/29`（日時は `例: 2026/09/29 10:21`）とする。
  - 年を表示しない場合は `例: 9/29` とする。
  - 曜日を付ける場合は `例: 2026/10/05（月）` とする。
  - 週の始まりは日曜日（デフォルト）または月曜日とし、設定画面で切り替える（「カレンダー > 状態」参照）。
- 登録・参照できる期間
  - 「対象外」の期間（「リミット値」の `LIMITS.calendarMinYear`・`LIMITS.calendarYearsAhead`）は年月選択・日付入力で選択不可とし、APIでも拒否する。
- 同意
  - 初回登録時に利用規約・プライバシーポリシーへの同意を取得する
  - 利用規約・プライバシーポリシー改定時、同意を取得する
- 削除
  - 論理削除。削除日時を保存し、一定期間（`LIMITS.deletedRetentionDays`）経過後に物理削除する
  - 論理削除したデータは画面上は存在しないものとして扱う（復元機能は提供しない）。APIは差分取得で削除の事実だけを返す（「データ取得・同期」参照）
- 同時更新
  - あと勝ち
- オフライン
  - 不要（オンラインが前提）。ただしローカルDBに保存済みのデータは表示できる
- 端末への保存
  - 端末に保存するデータはローカルDB（IndexedDB）に統一し、localStorage・sessionStorage は使わない。

### 対象外

次の機能は提供しない。

- 2021/01/01より前の予定の登録・参照
- 現在年より4年以上先（例: 2026/10/03の場合、2030/01/01～）の予定の登録・参照
- 繰り返しイベント
- 日表示・年表示（カレンダーは月表示と1週間表示のみ）
- 複数グループへの参加
- 外部カレンダー（Googleカレンダー等）との連携
- 削除したデータの復元
- CSVのインポート

### ログイン・同意

- Googleでログインする。初回登録時、または利用規約・プライバシーポリシー改定後に初めてアプリを開いたときに同意を取得する。

#### 画面

- ログイン画面
  - ロゴ・アプリ名・キャッチコピーを画面上部の余白の中央に、「Googleでログイン」ボタンと注記（「はじめての方は、ログインのあとに利用規約・プライバシーポリシーへの同意をお願いします。」）を画面下部に表示する。タブレット・PCでは左右中央に置く。
  - 「Googleでログイン」ボタン（Google 公式のボタン。同意前でも押せる）
  - ログインに失敗した場合（IDトークンを検証できない等）は「ログインできませんでした。もう一度お試しください」と表示する。
- 同意画面
  - 利用規約・プライバシーポリシーへのリンク（新しいタブで開く）
  - 「利用規約とプライバシーポリシーに同意します」チェックボックス
  - 「同意してはじめる」ボタン（チェックするまで押せない）

#### 操作

- 未ログインで任意の画面を開くとログイン画面を表示し、ログイン後に元の画面へ戻る。
- ログインすると、APIがIDトークンを検証する。登録済みのユーザーはそのまま元の画面へ進む。未登録のユーザーには同意画面を表示し、同意した後に登録する（同意した規約のバージョンを登録時にサーバーで記録する）。
- 同意済みのバージョンが現在の利用規約・プライバシーポリシーのバージョンより古い場合、ログイン済みでも同意画面を表示し、同意するまで他の画面を利用できない。
- ログイン状態は `LIMITS.sessionDays` 日保持する。期限切れ後はログイン画面を表示する。
- 設定画面からログアウトできる。ログアウトしてもローカルDBのデータは残す（再ログイン時は差分取得で済むため）。ログアウト中はローカルDBのデータを表示しない。
- ローカルDBのデータと異なるユーザーでログインした場合は、ローカルDBのデータを全て消去してから取得する。

### カレンダー

- 個人の予定とグループの予定のイベントを1つのカレンダーに表示する。月表示と1週間表示を切り替えられる。

#### 状態

| 状態                     | 値                                            | 単位             |
| ------------------------ | --------------------------------------------- | ---------------- |
| 表示形式                 | 月（デフォルト） / 週                         | 個人（端末ごと） |
| 予定フィルター           | 予定ごとの表示/非表示（デフォルト: 全て表示） | 個人（端末ごと） |
| 月表示のイベント表示形式 | バー（デフォルト） / ドット                   | 個人（端末ごと） |
| 週の始まり               | 日曜日（デフォルト） / 月曜日                 | 個人（端末ごと） |

- 状態はローカルDBに保存し、APIには送らない。
- 新しく追加された予定はフィルターで表示状態とする。

#### 画面

- 共通（ヘッダー）
  - 1段目: 表示中の期間（月表示は「2026年10月」、1週間表示は「10/1（木）– 10/7（水）」。タップで年月選択）、前へ・次へボタン、「今日」ボタン
    - 「今日」ボタンは、当日が選択中で、かつ表示中の月（1週間表示は表示中の7日）に当日が含まれるときは押せない状態にする（当日を表示中かどうかをボタンでも判断できるようにする）。
  - 2段目: 左半分に選択中の日（未選択なら当日）とその日のイベント件数（予定フィルター適用後。例: 「10/5(月) : 2 件」）、右半分に月/週切り替え
  - 予定フィルター（予定ごとのチップ。個人の予定は人型アイコン、グループの予定はグループアイコン、選択中はチェックアイコンと予定の色で表示）
  - 右下にイベント登録ボタン（FAB）
- カレンダー（月表示）
  - Vuetify4の `v-calendar`（view-mode="month"）を使用する。
  - 日付、曜日。日曜・祝日・休日は赤、土曜は青で表示する。当日は日付を塗りつぶす。前月・翌月の日付は薄く表示する。
  - 祝日・休日は日付枠内に赤字で名称を表示する。
  - イベントは予定の色で表示する。
    - バー: イベント名を表示する。日跨りのイベントは連続したバーで表示する。
    - ドット: 予定の色のドットを最大 `LIMITS.monthDotsPerDay` 個表示する。
  - 月表示は1画面（ヘッダー・ボトムナビゲーションを除いた領域）にスクロールなしで収める。日付枠に表示できるバーの件数は枠の高さから算出し、収まらない件数は「+N」と表示する。
- カレンダー（1週間表示）
  - `v-list` による独自実装。当日を中心に前後3日、計7日を表示する（週の始まりの設定に関係なく当日が中心）。
    （例: 当日が4|日の場合、1|木・2|金・3|土・4|日・5|月・6|火・7|水）
  - 日ごとに日付・曜日・祝日名・イベント一覧を表示する。イベントがない日は「予定なし」と表示する。
  - 日跨りのイベントは各日に「n/m日目」を付けて表示する。
  - 画像が添付されたイベントにはクリップアイコンを表示する。
- 年月選択
  - `v-dialog` + `v-date-picker-months` / `v-date-picker-years`。現在の表示月を塗りつぶし、当月を枠線で示す。
  - 選択できる範囲（例: 「2021年1月 〜 2029年12月 を表示できます」）を表示する。

#### 操作

- 年月選択: 選択した年月の月表示（週表示中はその月の1日を中心とした1週間表示）に移動する。
- 前へ・次へ: 月表示は1か月、1週間表示は7日単位で移動する。
- 今日: 当日を含む月（1週間表示は当日中心）に戻る。
- 予定フィルター: チップのタップで予定ごとに表示/非表示を切り替える（複数選択）。チップの長押し（0.5秒）でその予定だけを表示し、それ以外を非表示にする。フィルターはローカルDBのデータに対して画面側で適用し、APIを呼ばない。
- 月表示で日付枠をタップすると、その日のイベント一覧（ボトムシート）を表示する。一覧のイベントをタップするとイベント詳細を表示する。一覧の日付の右に「イベント追加」ボタンを置き、その日を開始日としてイベント登録画面を開く。
- 1週間表示でイベントをタップするとイベント詳細を表示する。イベント以外（日付・曜日の部分等）をタップするとその日を選択し、その日を中心とした7日の表示に切り替える（残る日はスクロールするように移動する）。
- 月表示から1週間表示に切り替えたときは、選択中の日（未選択なら当日）を中心とした7日を表示する。
- スワイプ: 月表示は左右（左で次月、右で前月）、1週間表示は上下のフリック（上で次週、下で前週）で、前へ/次へボタンと同じ切り替えをする。「登録・参照できる期間」の外へは切り替えない。1週間表示の一覧は縦にスクロールするため、素早いフリック（0.3秒以内に50px以上）だけを週の切り替えとし、ゆっくりしたドラッグは一覧のスクロールとする。切り替えた月・週は、来た方向からスライドして表示する（表示形式の切り替えではスライドしない）。カレンダー部分の横スワイプはブラウザの戻る・進む操作にしない（`overscroll-behavior-x: none`）。
- FAB: 選択中の日（未選択なら当日）を開始日としてイベント登録画面を開く。
- 年月の移動ではAPIを呼ばない（全データをローカルDBに保持しているため）。

#### 一覧

- 1日のイベントの並び順は、終日のイベント → 開始時刻の昇順 → 予定の並び順（「予定 > 一覧」参照）とする。
- 月表示の日付枠のバーも同じ順で表示する（日跨りのイベントは終日と同じ扱いで先頭に表示する）。

#### 祝日・休日

- 祝日・休日のデータはフロントエンドに同梱したライブラリ（例: `@holiday-jp/holiday_jp`）から取得し、APIを使わない。
- 法改正等で祝日が変わった場合はライブラリを更新する。

### イベント

- 予定に属する個々の出来事。登録・変更・削除・詳細表示ができる。画像を添付できる。

#### 項目

| 項目     | 備考                                                                                                                                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| タイトル | 必須。最大 `LIMITS.eventTitleMaxLength` 文字                                                                                                                                                                                                      |
| 予定     | 必須。個人の予定・グループの予定から選択する。選択した予定の公開範囲（「個人の予定は自分だけに表示されます」等）を表示する                                                                                                                        |
| トピック | 任意。選択した予定のトピックマスタから選択、または文字列を入力して新規登録する（「予定 > トピック」参照）                                                                                                                                         |
| 終日     | 必須。オン/オフ（デフォルト: オフ）                                                                                                                                                                                                               |
| 開始日   | 必須                                                                                                                                                                                                                                              |
| 開始時刻 | 終日オフの場合は必須。10分単位（`EVENT_TIME_STEP_MINUTES`）。5分単位だった頃に保存した時刻は、変更しなければそのまま保存できる                                                                                                                    |
| 終了日   | 必須。開始日以降。開始日から終了日までの日数（両端を含む）は最大 `LIMITS.eventMaxDays` 日                                                                                                                                                         |
| 終了時刻 | 終日オフの場合は必須。10分単位（開始時刻と同じ）。開始日時より後                                                                                                                                                                                  |
| 通知     | 任意。なし（デフォルト）/ 開始時刻 / 5分前 / 10分前 / 30分前 / 1時間前 / 1日前。終日の場合は なし / 当日9:00 / 前日9:00                                                                                                                           |
| 場所     | 任意。最大 `LIMITS.eventLocationMaxLength` 文字。施設名・住所・緯度経度（例: `43.0687,141.3508`）のいずれか。イベント詳細に地図を表示する。登録・編集画面では、入力が止まって1秒後に場所欄の下へ地図を表示する（1秒以内に再入力したら検索しない） |
| URL      | 任意。最大 `LIMITS.eventUrlMaxLength` 文字。`http://` または `https://` で始まるURLのみ（`javascript:` 等はリンクにすると危険なため画面・APIで拒否する）。お祭り・勉強会のページ等。イベント詳細から開ける                                        |
| メモ     | 任意。最大 `LIMITS.eventMemoMaxLength` 文字                                                                                                                                                                                                       |
| 画像     | 任意。最大 `LIMITS.imagesPerEvent` 枚（「イベント > 画像」参照）                                                                                                                                                                                  |

#### 画面

- イベント詳細（`v-bottom-sheet`）
  - 予定名（予定の色）、公開範囲（「個人 · 自分のみ表示」/「グループ · メンバーに公開」）、トピック、タイトル
  - 日時（例: `2026/10/05（月）10:00 – 11:00`、終日は日付のみ、日跨りは開始・終了の日付）
  - 通知、場所、URL、メモ
  - 場所がある場合: 場所（タップで Google マップを開く。スマホでは地図アプリ）と、その場所の Google マップの埋め込み。どちらも APIキー不要の呼び出し（地図リンクは公開仕様の Maps URLs、埋め込みは非公開仕様の `output=embed`。埋め込みが使えなくなった場合もリンクは使える）。CSP の `frame-src` に `https://www.google.com/maps` を許可する
  - URLがある場合: URL（タップで新しいタブ・ブラウザで開く）。表示前にも http/https であることを確認し、それ以外はリンクにしない
  - 画像のサムネイル（タップで全画面表示。ピンチ・マウスホイールで画像を拡大し、ドラッグで移動できる。画面全体は拡大しない。左上に常に閉じるボタンを表示する）
  - 最終更新（グループの予定は「更新者のメンバー名 · 更新 2026/09/29 10:21」、個人の予定は「更新 2026/09/29 10:21」）。更新者がグループを抜けている場合は「元メンバー」と表示する
  - 編集ボタン、削除ボタン
- イベント登録・編集（`v-dialog` fullscreen）
  - 項目の入力欄（`v-text-field` / `v-select` / `v-combobox` / `v-switch` / `v-textarea`、variant="outlined"）、保存ボタン
  - 日付は `v-date-input`。「登録・参照できる期間」外の日付は選択不可。
  - 開始・終了時刻は 10分刻みの `v-select`。
  - 端末の戻る操作・×ボタンはルートを戻ることで閉じる（`v-dialog` の `closeOnBack` はオフ。オンだと persistent なダイアログが戻る操作を取り消してしまう）。
  - 画像欄: 添付済み画像のサムネイル（各画像に削除ボタン）、「画像を追加」ボタン、貼り付け領域
  - 編集時は「このイベントを削除」ボタンを表示する。

#### 画像

- 追加方法
  - 貼り付け: 登録・編集画面でクリップボードの画像を貼り付ける（PCは Ctrl+V / ⌘+V、スマートフォンは貼り付け領域の長押し →「ペースト」）
  - ファイル選択: 「画像を追加」から端末の写真・ファイルを選ぶ
- 端末側で長辺 `LIMITS.imageMaxPx` px 以下に縮小し、JPEG（品質0.85）に変換してからアップロードする。変換後のサイズが `LIMITS.imageMaxBytes` を超える場合は追加できない。
- 画像の保存容量は、個人・グループごとに合計 `LIMITS.imageStorageBytes` まで。超える場合は追加できない。
- 画像は変更できない（差し替えは削除して追加する）。
- 画像はAPI（`/api/images/:id`）経由で配信し、参照権限をAPIで検証する。画像は不変のため、ブラウザのHTTPキャッシュ（`Cache-Control: private, max-age=31536000, immutable`）に保持し、ローカルDBには保存しない。

#### 登録・変更・削除

- 予定ごと・1日あたりのイベント件数は `LIMITS.eventsPerDayPerSchedule` 件まで。日跨りのイベントは期間内の各日に1件と数える。上限を超える場合は登録・変更できない。
- 予定の変更（例: 個人の予定 → グループの予定）もできる。
  - 変更先の予定のトピックマスタに同名のトピックがなければトピックは未設定になる。
  - 公開範囲が変わる場合は、元のイベントを削除し、新しいイベントとして登録する（IDが変わる。画像も引き継ぐ）。差分取得で公開範囲ごとに削除・登録を正しく伝えるため。
- 保存時は、イベントの保存 → 追加した画像のアップロード → 削除した画像の削除 の順にAPIを呼ぶ。
- 削除時は確認ダイアログを表示する。イベントを削除すると添付した画像も削除する。

### 予定

- イベントのまとまり。個人の予定とグループの予定がある。予定ごとにトピックマスタを持つ。

#### 項目

| 項目     | 備考                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 公開範囲 | 必須。個人 / グループ（グループ参加時のみ選択可）。登録後は変更できない  |
| 予定名   | 必須。最大 `LIMITS.scheduleNameMaxLength` 文字。同じ公開範囲内で重複不可 |
| 色       | 必須。既定の12色から選択する                                             |

- 予定の件数は、個人の予定はユーザーごとに `LIMITS.personalSchedules` 件、グループの予定はグループごとに `LIMITS.groupSchedules` 件まで。

#### 画面

- 予定の管理（`v-list`）
  - 個人の予定とグループの予定を混在させ、ユーザーが設定した並び順で表示する。
  - 各行にドラッグハンドル、色、予定名、公開範囲のアイコン（個人: 鍵 / グループ: グループ）、表示中の月のイベント件数（例: 「今月 9件」）、メニュー（編集・トピック管理・削除）を表示する。
  - 一覧の上部に公開範囲の説明（「個人 · 自分だけに表示」「グループ「山田家」· メンバー3人に公開」）を表示する。
  - 「予定を追加」ボタン。追加時に公開範囲（個人 / グループ）を選択する。
  - グループ未参加の場合、「グループを作成・参加」への導線を表示する。

#### 一覧

- 並び順はユーザーごとに設定でき、個人の予定とグループの予定を混在させて並べられる。ドラッグで並び替える。
- 並び順はユーザーごとにDBに保存し（グループの予定の並び順も各メンバーで別々）、端末間で共有する。
- 並び順に含まれない予定（新規作成された予定、他のメンバーが作成したグループの予定）は末尾に登録日時の昇順で表示する。自分が作成した予定は作成時に並び順の末尾に加える。
- カレンダーの予定フィルター、イベント登録の予定選択も同じ順とする。

#### トピック

- トピックマスタは予定ごとに持つ。件数は予定ごとに `LIMITS.topicsPerSchedule` 件まで、トピック名は最大 `LIMITS.topicNameMaxLength` 文字。
- イベント登録・編集のトピック欄（`v-combobox`）で、既存のトピックを候補から選ぶか、文字列を入力する。入力した文字列と同名のトピックがなければ、イベント保存時に自動でトピックマスタに登録する（別画面での事前登録は不要）。
- 予定の管理画面のトピック管理で、トピック名の変更・削除ができる。削除したトピックが設定されたイベントは、トピック未設定になる。
- トピック名は予定内で重複不可。

#### 登録・変更・削除

- 予定を削除すると、その予定のトピック・イベント・画像も削除する。削除時はイベント件数を示した確認ダイアログを表示する。

### グループ

- 家族等で予定を共有する単位。1ユーザーが参加できるグループは0〜1つ。QRコード（招待リンク）で招待する。

#### 項目

| 項目       | 備考                                                               |
| ---------- | ------------------------------------------------------------------ |
| グループ名 | 必須。最大 `LIMITS.groupNameMaxLength` 文字                        |
| メンバー名 | 必須。最大 `LIMITS.memberNameMaxLength` 文字。グループ内で重複不可 |

- メンバー数はグループごとに `LIMITS.groupMembers` 人まで。

#### 画面

- グループ（未参加）
  - 「グループを作成」ボタン（グループ名・自分のメンバー名を入力）と、招待リンクから参加する方法の説明
- グループ（参加中）
  - グループ名（作成者は編集可）
  - 招待カード: QRコード（`qrcode` ライブラリでクライアント側で生成）、「家族のスマホのカメラで読み取るとグループに参加できます」、有効期限、「リンクをコピー」、「再発行」
  - メンバー一覧（`v-list`）: メンバー名のイニシャル、メンバー名（自分は「（あなた）」付き）、「作成者」または参加日、メニュー（自分: メンバー名変更・脱退、作成者から他メンバー: 除外）
  - 作成者のみ「グループを削除」
- グループ参加（招待リンクを開いたとき）
  - グループ名、メンバー名の入力欄、「参加」ボタン

#### 操作

- 招待リンクは `LIMITS.inviteExpiryHours` 時間有効。グループ作成時に発行する。期限切れ後は招待カードに「期限切れ」と表示し、再発行を促す。
- 再発行すると以前の招待リンクは無効になる。
- 招待リンクを開いた未ログインのユーザーは、ログイン（初回は同意）後にグループ参加画面を表示する。
- 次の場合は参加できず、理由を表示する: 招待リンクが無効・期限切れ、既に別のグループに参加中、メンバー数が上限。
- 脱退・除外されたユーザーは、そのグループのデータを参照できなくなる（ローカルDBからも消去する）。グループの予定・イベントはグループに残る。
- グループを削除すると、グループの予定・トピック・イベント・画像も削除し、全メンバーが未参加になる。
- 脱退・除外・削除時は確認ダイアログを表示する。

### 設定

- アカウントと表示に関する設定、CSVダウンロード。

#### 画面

- 月表示のイベント表示形式（バー / ドット）
- 週の始まり（日曜日 / 月曜日）。月表示の列の並び（`v-calendar` の `first-day-of-week`）と、日付入力（`v-date-input`）のカレンダーに反映する
- 通知（プッシュ通知の許可状態と、この端末で受け取るかのオン/オフ）
  - iPhone・iPadでブラウザから開いている場合（iOSはホーム画面に追加したPWAにしか通知を届けない）は、オン/オフの代わりに「インストール」ボタンと「iPhone・iPadでは、ホーム画面に追加したアプリで通知を受け取れます」を表示する。ボタンは「アプリをインストール」と同じiPhone・iPad向けの追加方法のダイアログを開く。iPadOSのSafariはMacと同じUser-Agentを名乗るため、タッチ操作に対応しているか（`navigator.maxTouchPoints`）でMacと見分ける（Macはブラウザのままでも通知を受け取れるため、この案内は出さない）
- CSVダウンロード
- アプリをインストール（PWA）。インストール済み（ホーム画面から開いている）の場合は表示しない
  - ブラウザがインストールのプロンプト（`beforeinstallprompt`。Chrome・Edge・Android）を出せる場合は、それを表示する。プロンプトは画面を開く前に届くことがあるため、起動時から受け取っておく（ブラウザ標準のインストール案内バナーの代わりにこのボタンを使う）
  - 出せない場合（iPhone・iPadのSafari等）は、追加方法をダイアログで案内する。iPhone・iPad: 「Safari の共有ボタンをタップし、「ホーム画面に追加」を選んでください。「Webアプリとして開く」はオンのままにします。」、それ以外: ブラウザのメニューの「アプリをインストール」/「ホーム画面に追加」
- 利用規約・プライバシーポリシーへのリンク
- ログアウト
- この端末のデータを消去
- 退会

#### CSVダウンロード

- ダイアログで予定を選び（複数選択、デフォルト: 全て）、選んだ予定のイベントをCSVでダウンロードする。
- ローカルDBのデータから端末側で生成し、APIを呼ばない（ダウンロード前に「データ取得・同期」の同期を1回行う）。
- 形式: UTF-8（BOM付き、Excelで文字化けしないため）、改行はCRLF、全項目をダブルクォートで囲む。先頭が `=` `+` `-` `@` の値は先頭に `'` を付ける（CSVインジェクション対策）。
- 列: 予定、公開範囲、トピック、タイトル、開始日、開始時刻、終了日、終了時刻、終日、通知、場所、URL、メモ、最終更新者、最終更新日時。画像は含めない。
- 並び順: 開始日 → 開始時刻 → 予定の並び順。
- ファイル名: `chocosuke_YYYYMMDD.csv`（ダウンロード日）。

#### この端末のデータを消去

- 共用の端末等で、端末に残ったデータを消すための操作。ログアウトではローカルDBのデータを残すため（「ログイン・同意」参照）、別に用意する。
- 確認ダイアログ（「この端末に保存したデータを消去してログアウトします。サーバーのデータは消えません。」）を表示する。
- 実行すると次を行う。
  - ローカルDBの全データ（画面の表示状態を含む）を消去する。
  - この端末のプッシュ通知の購読を解除し、購読情報をサーバーから削除する。
  - 画像のブラウザキャッシュを消去する（APIの応答ヘッダー `Clear-Site-Data: "cache"` による。対応していないブラウザでは残る）。
  - ログアウトしてログイン画面を表示する（ログイン中のままだと直後の同期でデータが再保存されるため）。
- サーバーのデータ・他の端末のデータは消えない。再度ログインすると全件取得する。

#### 退会

- 退会すると、個人の予定・トピック・イベント・画像を削除し、グループから脱退する（作成者の場合は「権限」の※に従う）。端末のローカルDBのデータも消去する。
- 確認ダイアログを表示する。退会後に同じGoogleアカウントでログインした場合は新規ユーザーとして扱う。

### 通知

- イベントの通知をPWAのプッシュ通知（Web Push）で送る。

#### 詳細

- 通知を受け取るには、端末ごとに設定画面で通知を許可する（iOSはホーム画面に追加したPWAのみ対応）。
- 通知先は、個人の予定のイベントは本人、グループの予定のイベントはグループの全メンバー（通知を許可した端末）とする。
- 通知日時（イベント保存時に算出）になったイベントを、Cloudflare Workers の Cron Trigger（1分ごと）で検索して送信する。送信は最大1分程度遅れることがある。
- 通知日時から10分以上過ぎた通知は送らずに破棄する（Cron の停止後に古い通知がまとめて届くのを防ぐため）。
- 送信後は通知日時を消去する（`events.notify_at` を NULL にする。リビジョンは上げない）。
- 通知内容: タイトル「イベントのタイトル」、本文「日時 · 予定名」。タップでアプリのイベント詳細を開く。
- 送信先から無効と応答された購読情報は削除する。

### データ取得・同期

- Cloudflare D1 の読み取り行数を抑えるため、全データをローカルDBに永続化し、以降は前回取得以降に更新されたレコードだけをAPIで取得する（差分取得）。

#### 同期の単位とリビジョン

- 同期は「個人」「グループ」の2単位で行う。
- 単位ごとにリビジョン（連番）を持つ（個人: `users.rev`、グループ: `groups.rev`）。
- 同期対象の全テーブル（予定・トピック・イベント・画像）は `owner_id`（users.id または groups.id）と `rev`（最後に更新されたときの単位のリビジョン）を持ち、`(owner_id, rev)` にインデックスを付ける。
- リビジョンを上げる操作
  - 個人: 個人のデータ（予定・トピック・イベント・画像・予定の並び順）の登録・変更・削除
  - グループ: グループのデータ（グループ名・招待リンク・メンバー・メンバー名・予定・トピック・イベント・画像）の登録・変更・削除
- 書き込みは D1 の `batch`（トランザクション）で、単位のリビジョンを +1 する更新と、対象レコードの `rev` をその値にする更新を一体で行う。D1 は書き込みを順に処理するため、リビジョンの順と書き込みの順が一致し、取りこぼしが起きない（更新日時を使うと、同時に保存したときやサーバー時刻のずれで取りこぼすため使わない）。
- 1回の操作で複数のレコードを更新する場合（配下の削除、公開範囲をまたぐ移動等）は、同じ `batch` 内で行う。公開範囲をまたぐ移動は両方の単位のリビジョンを上げる。
- `updated_at` は表示用（「更新 2026/09/29 10:21」）として持ち、同期には使わない。
- 通知送信後の `events.notify_at` の消去ではリビジョンを上げない（画面に返さない値のため）。

#### 同期API

- 最終更新の確認と差分取得を1本のAPI（`GET /api/sync`）で行う。
- リクエスト: 端末が保持している個人のリビジョン、グループのID・リビジョン（未取得の単位は省略）
- 処理（読み取りは1つの `batch` で行い、整合したデータを返す）
  1. `users` と `groups` の行を読み、現在のリビジョンと `group_id` を得る。
  2. 単位ごとに、リビジョンが端末と同じなら何も返さない（読み取りは2行で終わる）。
  3. リビジョンが新しい単位は、`owner_id = ? AND rev > ?（端末のリビジョン）` のレコードを、論理削除済みのものも含めて返す。
  4. 全件取得が必要な単位（下記）は、`owner_id = ? AND deleted_at IS NULL` のレコードを全て返し、全件であることを示す。
- 応答
  - 単位ごとに: 現在のリビジョン、全件かどうか、予定・トピック・イベント・画像のレコード
  - 個人が変わった場合: 予定の並び順
  - グループが変わった場合: グループ情報・メンバー一覧（最大 `LIMITS.groupMembers` 行。毎回全件）
  - 現在の `group_id`（未参加なら NULL）
- 呼ぶタイミング: アプリ起動時、アプリが前面に戻ったとき、前面にある間は `LIMITS.syncCheckIntervalMinutes` 分ごと、自分が登録・変更・削除した直後

#### 全件取得する場合

- 端末にリビジョンがないとき（初回ログイン・別端末・ローカルDBの消去後・ローカルDBの構造の変更後）
- 端末のリビジョンが、その単位の物理削除済みリビジョン（`users.purged_rev` / `groups.purged_rev`）より小さいとき（削除の記録が物理削除され、差分で受け取れないため。APIで判定する）
- 参加中のグループが変わったとき（グループ単位のみ。端末の `group_id` と応答の `group_id` が異なる場合、端末は変わる前のグループのデータをローカルDBから消去する。応答が NULL ならグループのデータを消去するだけ）

#### 画面での反映

- 応答のレコードをIDでローカルDBに上書き保存し、`deleted_at` があるレコードはローカルDBから削除する。全件の単位は、その単位のデータを入れ替える。
- レコードの反映とリビジョンの記録は、同じ IndexedDB トランザクションで行う（途中で失敗してもデータとリビジョンがずれないため）。
- 自分の登録・変更・削除も、APIの応答で画面を直接書き換えず、直後の同期で反映する。
- フィルター・件数集計（「今月 n件」）・並び替え・CSV生成はローカルDBのデータから画面側で行い、APIを呼ばない。
- 複数タブで開いた場合、タブ間の連携はしない（各タブが前面に来たときに同期する）。

#### 削除の伝え方

- 親を削除したら、配下のレコードもサーバー側で1件ずつ論理削除し（`deleted_at` と新しい `rev` を設定）、差分取得で伝える。画面は親子関係をたどらず、削除済みのレコードを消すだけにする。

| 操作                       | サーバーで行うこと                                                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 予定の削除                 | 予定と、配下のトピック・イベント・画像を論理削除する                                                                       |
| トピックの削除             | トピックを論理削除し、設定されていたイベントの `topic_id` を NULL にする                                                   |
| イベントの削除             | イベントと、添付した画像を論理削除する                                                                                     |
| 公開範囲をまたぐ予定の変更 | 元のイベント・画像を論理削除し、変更先の単位に新しいIDで登録する（R2のオブジェクトはコピーする）                           |
| グループの削除             | グループと配下の全データを論理削除し、全メンバーの `group_id` を NULL にする（端末へは `group_id` の変化で伝わる）         |
| 脱退・除外                 | 対象ユーザーの `group_id` を NULL にする（端末へは `group_id` の変化で伝わる。グループには残るメンバーの変更として伝わる） |
| 退会                       | 個人のデータを論理削除し、脱退と同じ処理を行う                                                                             |

- 物理削除（Cron Trigger、1日1回）は、`deleted_at` から `LIMITS.deletedRetentionDays` 日経過したレコードを削除し、削除したレコードの最大の `rev` で単位の `purged_rev` を更新する。

#### TanStack Query との役割分担

- `useQuery(['sync'])` の `queryFn` で、同期APIの呼び出し → ローカルDBへの反映 → メモリ上のデータを返す、を行う。
- 起動時はローカルDBの内容を `initialData` として即時に表示し、その後に同期する。
- 確認のタイミングは `refetchOnWindowFocus` と `refetchInterval`（`LIMITS.syncCheckIntervalMinutes`）で実現する。
- 登録・変更・削除は `useMutation` で行い、成功後に `invalidateQueries(['sync'])` で同期する。

### データ保持・プライバシー

- Googleアカウントから保存するのは識別子（sub）のみとし、氏名・メールアドレス・プロフィール画像は保存しない。
- 論理削除したデータ・退会したユーザーのデータは `LIMITS.deletedRetentionDays` 日後に Cron Trigger で物理削除する（画像はR2のオブジェクトも削除する）。
- 個人のデータは本人以外に公開しない。グループのデータはメンバー以外に公開しない（APIで検証する）。
- ローカルDBのデータは、別のユーザーでログインしたとき・退会したとき・設定画面の「この端末のデータを消去」を実行したときに消去する（ログアウトでは消去しない）。
- 利用規約・プライバシーポリシーをアプリ内で公開する。

### アーキテクチャ

- backend(API)
  - Hono on Cloudflare Workers（`apps/backend-worker`）
  - Cloudflare D1
  - Cloudflare R2（イベントの画像）
  - Cloudflare Workers Cron Trigger（通知送信: 1分ごと、物理削除: 1日1回）
- frontend
  - Vue3 + Vuetify4 の Webアプリ（PWA）
  - Service Worker の新しい版は、スナックバーの「更新」が押されるまで待機する（`registerType: 'prompt'`、「共通ルール > 画面 > アプリの更新」）。押されたら `skipWaiting` で切り替え、再読み込みする。開いている画面の下でキャッシュ済みのファイルを入れ替えないため。
  - Vuetify4のv-calendar
    https://vuetifyjs.com/ja/components/calendars/#section-4f7f304465b9
  - ローカルDB: IndexedDB + `idb`（「データ取得・同期」参照）
  - TanStack Query（同期・登録などのAPI呼び出しの管理）
  - 祝日: 同梱ライブラリ（例: `@holiday-jp/holiday_jp`）
  - QRコード: `qrcode`
  - 予定の並び替え: ドラッグ＆ドロップのライブラリ（例: `vue-draggable-plus`）
- 配信
  - 画面と API を同じオリジンで配信する。画面は `/`、API は `/api` 配下。
- 認証
  - Googleでログイン（Google Identity Services）。APIでIDトークンを検証し、署名付きのセッションCookie（HttpOnly・Secure・SameSite=Lax）を発行する。セッションはDBに保存しない（読み取り行数を増やさないため）。
  - 未登録のアカウントにはセッションを発行せず、同意画面のあとの登録API（IDトークンと同意した規約のバージョン）でユーザーを作成する（「ログイン・同意」参照）。
  - IDトークンの `aud` は Google のクライアントID（Workers のシークレット `GOOGLE_CLIENT_ID`）と照合する。クライアントIDが未設定の場合は、他アプリ向けのトークンを受け入れないよう、すべてのIDトークンを拒否する。
- リクエストの大きさ
  - リクエストボディは読み込む前に上限で拒否する（413）。画像のアップロードは `LIMITS.imageMaxBytes`、それ以外（JSON）は 64KB。
- 通知
  - Web Push（VAPID）。VAPIDの秘密鍵はWorkersのシークレットで管理する。
- プラン
  - Workers Paid プラン（$5/月）を前提とする。無料プランは Cron 1回あたりCPU 10ms・外部リクエスト50件の制限があり、同じ分に通知が集中すると送信しきれないため。

### データ仕様

仕様を満たす最小限のデータを保持する。導出できる値は都度集計する。

- 各テーブルの `id` は `crypto.randomUUID()` で生成する。
- 日時は INTEGER（UNIXエポックミリ秒）、日付は TEXT（`YYYY-MM-DD`、Asia/Tokyo）、時刻は TEXT（`HH:mm`、Asia/Tokyo）で保存する。
- `deleted_at` を持つテーブルは論理削除する。差分取得以外の検索は `deleted_at IS NULL` を条件にする。
- 同期対象のテーブル（schedules・topics・events・event_images）は `owner_id`・`rev` を持ち、`(owner_id, rev)` にインデックスを付ける。論理削除時も `rev` を更新する（「データ取得・同期」参照）。

#### ローカルDB（IndexedDB）

- ライブラリは `idb`（IndexedDB の薄いラッパー）を使う。全データを起動時にメモリへ読み込んで画面側で絞り込むため、検索機能を持つライブラリは使わない。

| ストア      | キー       | インデックス | 内容                                                                                                                                                                                 |
| ----------- | ---------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `schedules` | id         | owner_id     | 予定                                                                                                                                                                                 |
| `topics`    | id         | owner_id     | トピック                                                                                                                                                                             |
| `events`    | id         | owner_id     | イベント                                                                                                                                                                             |
| `images`    | id         | owner_id     | 画像のメタデータ                                                                                                                                                                     |
| `kv`        | 任意のキー | －           | ログイン中のユーザーID、単位ごとのリビジョン・`group_id`、グループ情報・メンバー一覧、予定の並び順、画面の表示状態（表示形式・予定フィルター・月表示のイベント表示形式・週の始まり） |

- 画像のファイル自体は保存しない（ブラウザのHTTPキャッシュに任せる）。

#### DBの外で管理するデータ

- **利用規約・プライバシーポリシー:** 本文はフロントエンドに静的ページとして同梱する。現在のバージョンは改定日（`YYYY-MM-DD`）とし、コード上の定数（`packages/utils/src/terms/terms.ts` の `TERMS_VERSION`）で管理する。本文を変えたら改定日に更新する。
- **祝日・休日:** フロントエンドに同梱したライブラリで判定する。
- **予定の色（12色）:** フロントエンドの定数で管理する。DBにはキーのみ保存する。
- **VAPID鍵・Google OAuth クライアントID・セッション署名鍵:** Workers のシークレット。公開してよい値（クライアントID・VAPID公開鍵）は、フロントエンドにもビルド時の環境変数で渡す（ルートの `AGENTS.md`「Public config values for the frontend」）。
